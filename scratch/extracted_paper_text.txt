Abstract—Task failures in cloud clusters waste resources and disrupt dependent services, making early prediction highly valuable. A recent deep learning baseline classifies aggregated snapshot records of task events but omits explicit temporal windows, lead-time measurement, class imbalance treatments, chronological splitting, and cross-dataset evaluation. We present a robust temporal framework for early failure prediction designed to resolve these gaps. Five-minute usage traces are transformed into sliding windows with causal rolling features, and each window is labelled normal, warning, or critical based on the time remaining before abnormal termination. A stacked long short-term memory (LSTM) network and a lightweight Transformer encoder classify the windows using focal loss, while a snapshot baseline isolates the contribution of temporal context. Evaluation relies on a chronological split grouped by task, eliminating data leakage, alongside a dedicated lead-time metric reporting detection rate, advance notice, and false alarms. While temporal modelling itself is established, our core contribution is a unified, leakage-free evaluation architecture that incorporates rigorous cross-dataset transfer testing. On the primary Google cluster trace, the optimal LSTM model achieves a macro F1-score of 0.87 and a median lead time of 12.5 minutes, significantly outperforming the snapshot baseline’s F1-score of 0.68 and 0.0 minute lead time.

Index Terms—Cloud computing, early failure prediction, long short-term memory, Transformer, class imbalance, lead time, time-series classification

Introduction

Cloud platforms execute vast numbers of tasks across shared infrastructure, where anomalous task termination—via failure, eviction, or loss—wastes computational expenditure and delays dependent pipelines. An early warning provides schedulers the critical window necessary to intervene, such as by checkpointing or migrating the vulnerable task [14]. Public production traces, notably the Google Cluster Trace 2019 [17], [18], facilitate the development and benchmarking of such predictors on realistic operational data.

Predictors fundamentally divide into snapshot and temporal architectures. A snapshot predictor classifies a single feature

vector per task or event, whereas a temporal predictor analyses an ordered sequence of recent observations. This distinction is critical for early warning systems: an impending failure is frequently preceded by an evolutionary trajectory—such as steadily climbing memory utilisation—that a static snapshot captures poorly. Furthermore, snapshot models lack a direct mechanism to quantify the lead time ahead of a failure.

Aldomi et al. [1] investigate this problem on a curated sample of the Google Borg 2019 data containing nine task-event classes. Following min–max normalisation, they select the top fourteen features, train a gated recurrent unit (GRU) network, and route its penultimate-layer activations to random forest (RF), support vector machine (SVM), and k-nearest-neighbour (KNN) classifiers. Their GRU-RF pipeline achieves a root mean squared error (RMSE) of 0.1415 and an F1-score of 0.99 on the Fail class.

However, evaluated against the strict requirements of early warning systems, the baseline exhibits several architectural gaps. It does not implement a sliding temporal window, nor does it explicitly measure how far ahead of a failure a prediction is rendered. It lacks a dedicated treatment for severe class imbalance, despite test classes ranging from single instances to tens of thousands. Finally, it omits chronological splitting to prevent future-data leakage and restricts evaluation to a single dataset.

While temporal modelling via Long Short-Term Memory (LSTM) networks [15] and bidirectional variants has been explored for cluster failures [2], [3], [12], [13], what remains absent from the literature is a unified, leakage-free framework that explicitly measures operational lead time, integrates imbalance-aware objectives, tests cross-trace generalisation, and benchmarks LSTM and Transformer [16] encoders against snapshot pipelines under identical constraints.

This paper rectifies these limitations through four primary contributions:

Temporal windows (L1). Snapshot records are replaced

by sliding windows of five-minute steps incorporating causal rolling features, classified by stacked LSTM and lightweight Transformer encoders.

Lead time (L2). Windows are labelled by the time remaining before abnormal termination. A bespoke early-warning metric evaluates detection rate, lead time, and false alarms per 1000 task-steps.

Class imbalance (L3). Training integrates class-weighted or focal loss, restricting oversampling strictly to embeddings. Evaluation relies on macro-F1 and precision–recall area under the curve (PR-AUC).

Evaluation protocol (L4). A task-grouped chronological split prevents data leakage. Models are rigorously tested on auxiliary public traces [19], [20] in zero-shot and fine-tuned configurations.

Classifier Architectures and Training

Horizons are established at H1 = 3 (15 min) and H2 = 6 (30 min). The primary temporal model is a stacked LSTM (2 layers, 128 hidden units). The secondary model is a lightweight Transformer encoder (4 heads, 2 layers, dmodel = 64). To combat extreme class imbalance (NORMAL vastly outnumbering CRITICAL), training employs Focal Loss (γ = 2.0).

Evaluation Protocol

Data is partitioned chronologically (70/15/15) by timestamp, grouped strictly by task ID to guarantee no single task spans the train and test sets (preventing data leakage). The alert threshold parameter is set to k = 3 consecutive flags.
